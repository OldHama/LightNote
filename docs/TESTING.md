# LightNote 테스트 절차

## 자동 검사

프로젝트 루트에서 실행합니다.

```sh
swift test
./scripts/build.sh
build/LightNote.app/Contents/MacOS/LightNote --self-test
```

모델 테스트는 10,000개 좌표·압력의 정확한 저장 복원, 점의 경계, 손상 JSON, 미래 파일 버전, 중복 획 ID 및 잘못된 렌더링 값을 확인합니다.

앱 내부 통합 검사는 실제 NSView에 합성 NSEvent를 전달합니다. 100개 점, 2,002개 샘플을 가진 빠른 방향 전환 획, 필기 중 저장 이후에도 좌표 수집 유지, 색상/두께, undo/redo, 입력 중단 후 고아 drag 무시, 점의 실제 비트맵 픽셀, 디스크 저장/재읽기, 손상 파일 읽기 실패 후 기존 상태 보존을 확인합니다. 이 검사는 실제 OS 입력 전달·Sidecar·사람이 느끼는 지연을 검증하지 않습니다. UI 조작 검증과 분리해서 해석해야 합니다.

## 마우스 실사용 확인

1. 앱 실행 후 50개의 빠른 점을 찍습니다. 점이 빠지거나 투명해지지 않는지 확인합니다.
2. 작은 글씨, 원, 지그재그를 빠르게 반복합니다. 획의 시작·끝과 방향 전환을 확인합니다.
3. 색상 네 가지와 두께 다섯 가지를 바꿉니다. 변경 전 획은 그대로 유지되어야 합니다.
4. 20획을 그린 후 ⌘Z를 20번, ⌘⇧Z를 20번 누릅니다. 순서와 색상·두께를 비교합니다.
5. 저장 후 닫고 ⌘O로 다시 엽니다. 점·좌표·색상·두께가 그대로인지 확인합니다.
6. 창 두 개에서 각각 입력하고 저장합니다. 서로의 획이 섞이지 않아야 합니다.
7. 창 크기 조절, 스크롤, 전체 화면, 창 밖 mouseUp을 점검합니다.
8. 문서 이름 입력과 색상 패널 텍스트 입력 중 P가 입력을 가로채지 않는지 확인합니다.
9. 잘못된 JSON/미래 버전 파일을 엽니다. 오류가 표시되고 이미 열린 문서는 유지되어야 합니다.
10. 읽기 전용 위치 저장 시 오류 안내 후 정상 위치에 다시 저장할 수 있는지 확인합니다.

## 자동 저장·비정상 종료 (별도 수동 확인 필요)

실제 노트 대신 복제한 테스트 문서를 사용합니다.

1. 저장한 문서에 식별 가능한 획을 추가하고 20초 이상 입력 없이 기다립니다.
2. 디스크 `.lightnote`의 좌표 개수가 늘었는지 확인합니다.
3. 테스트 앱만 강제 종료하고 재실행한 뒤 마지막 자동 저장까지 복원되는지 확인합니다.
4. 이름 없는 문서도 같은 방식으로 확인합니다. OS의 '앱 종료 시 윈도우 닫기' 설정을 기록합니다.
5. 저장 직전/도중 강제 종료 테스트 후 기존 파일이 JSON으로 정상 해독되는지 확인합니다.

최근 자동 저장 이후의 미저장 획은 손실될 수 있습니다. 강제 종료 순간까지의 완전 복구는 MVP의 보장 범위가 아닙니다.

## Sidecar 실기기 확인 (미실시)

1. Mac/iPad 모델, macOS/iPadOS 버전, 연결 방식, 디스플레이 배율을 기록합니다.
2. Sidecar로 앱 창을 옮긴 뒤 Pencil로 점 100개와 빠른 글씨를 씁니다.
3. 아래 로그에서 `tablet` 개수를 확인합니다. 0이라면 압력 지원을 추정하지 않습니다.
4. Pencil을 떼고 다시 대거나 창을 비활성화했을 때 획이 멀리 연결되지 않는지 확인합니다.
5. 필기 중 Sidecar를 해제한 뒤 재연결하고 동일 테스트를 반복합니다.
6. 창을 Mac 화면과 iPad 화면 사이로 이동하고 Retina 배율을 바꾼 뒤 좌표와 두께를 확인합니다.
7. 실제 눈으로 본 입력 누락과 앱 이벤트 수를 구분해 기록합니다. 필요하면 고속 촬영으로 펜 접촉부터 표시까지의 지연을 측정합니다.

## 진단 로그

개인 필기 좌표나 파일 경로는 로그에 남기지 않습니다. 획 종료 시 샘플 수·이벤트 수·tablet 이벤트 수·종료 이유만 기록합니다.

```sh
log stream --level debug --predicate 'subsystem == "com.lightnote.app"'
```

누락 재현 시 앱 버전, 디스플레이 설정, 입력 장치, 재현 순서, 샘플 수와 로그 시간을 기록합니다. `finish=display-change/app-inactive/window-inactive/proximity-exit`은 입력 중단을 확정한 이유입니다.

## Instruments 측정 (미실시)

Release 빌드로 **Time Profiler**, **Allocations**, **Leaks**, **Animation Hitches**를 실행합니다. Xcode 프로젝트의 Profile은 Release를 사용합니다. Xcode 설치가 정상화되기 전에는 GUI Instruments 실행 가능 여부를 따로 확인합니다.

- 빈 페이지 / 1,000획 / 5,000획에서 같은 30초 입력 패턴을 비교합니다.
- Main thread의 mouseDragged, draw, JSON 인코딩 시간을 분리합니다.
- 입력 중과 유휴 상태 CPU, 실제 메모리, 저장 직후 최대 메모리를 기록합니다.
- 30분 입력, undo/redo, 문서 닫기 후 CGPath/좌표 배열이 회수되는지 확인합니다.
- 첫 입력/평균/P95 표시 지연을 별도 측정하고 Mac·Sidecar를 나눠 기록합니다.

현재는 단일 페이지입니다. 수천 획 경계 검사와 저장 시 전체 JSON 인코딩이 다음 최적화 후보이며, 측정 전 성능 목표를 달성했다고 판단하지 않습니다.

## 모눈 용지 확인

1. 용지 메뉴에서 모눈을 선택하고 기존 필기가 그대로 유지되는지 확인합니다.
2. 스크롤과 새 필기를 반복하여 격자 선이 이동하거나 부분적으로 사라지지 않는지 확인합니다.
3. 용지 변경 직후 ⌘Z / ⌘⇧Z로 무지 / 모눈을 복원합니다.
4. 모눈 문서를 저장하고 다시 열어 설정과 필기가 복원되는지 확인합니다.
5. 기존 paperStyle 필드가 없는 문서는 무지로 열려야 합니다.

추가 자동 검사: 모눈 설정 직렬화·이전 파일 호환성, 용지 변경 중 필기 보존, 용지 Undo/Redo, 실제 모눈 픽셀 렌더링을 확인합니다.

## 획 지우개

1. E를 누르거나 획 지우개 버튼을 선택한 후 점과 긴 선을 각각 클릭합니다. 닿은 획만 전체 삭제되어야 합니다.
2. 여러 획을 빠르게 가로질러 문지릅니다. 이벤트 사이를 통과한 획도 지워져야 합니다.
3. ⌘Z 한 번으로 한 번 문지른 작업 전체가 원래 순서로 복원되고 ⌘⇧Z로 다시 지워져야 합니다.
4. 빈 용지를 문질러도 새 획이나 불필요한 실행 취소 작업이 생기지 않아야 합니다.
5. P로 펜을 선택하여 기존 색상·두께로 다시 필기합니다.
6. 지운 문서를 저장하고 재실행하여 삭제가 유지되는지 확인합니다.
7. 지우는 중 창 비활성화 또는 도구 변경 후 다음 입력과 연결되지 않는지 확인합니다.

자동 검사에서는 실제 NSView 합성 이벤트로 E/P 선택, 점 클릭 삭제, 빠른 이동으로 점 20개 삭제, 작업 단위 Undo/Redo, 복원 시 좌표와 획 순서 보존, 삭제 결과 직렬화를 검증합니다. 실제 Sidecar 지우개 조작은 별도 실기기 확인 대상입니다.

## 핀치 확대·축소

1. 트랙패드에서 두 손가락을 벌리거나 오므려 25~400%로 확대·축소합니다. 일반 두 손가락 스크롤은 페이지 이동으로 유지되어야 합니다.
2. 확대·축소 중심 부근 용지 위치가 갑자기 튀지 않는지 확인합니다.
3. 50% / 100% / 200%에서 같은 위치에 점과 획을 쓰고 E로 지웁니다. 입력·렌더링·지우개 위치가 일치해야 합니다.
4. 모눈, 필기, 점이 함께 확대되고 배율 변경만으로 문서가 수정 상태가 되지 않는지 확인합니다.
5. 하단 배율 표시를 클릭하면 100%로 복원되어야 합니다.
6. 핀치 후 필기와 실행 취소를 반복하고, 활성 필기 도중 핀치가 시작되면 이전 획과 비정상적으로 연결되지 않는지 확인합니다.

자동 통합 검사는 실제 NSScrollView를 50% / 200%로 변환하여 화면 좌표 배율, 역변환된 필기 좌표, 확대 상태의 획 지우기, 벡터 원본 불변, 100% 복원을 검증합니다. 물리적인 트랙패드 제스처 전달과 Sidecar 두 손가락 터치는 이 합성 입력 검사에 포함되지 않으며 별도 장치 확인이 필요합니다.

## 줌아웃 후 바깥 영역 회귀 검사

- 25%로 축소하고 창을 넓힙니다. 전체 뷰포트에 모눈이 이어지고 오른쪽·아래쪽에서도 필기를 시작할 수 있어야 합니다.
- 기존 A4 범위 밖에 점과 글씨를 쓰고 E로 지우기, Undo, 저장·재열기를 확인합니다.
- 무지/모눈을 전환해도 확장된 영역이 줄거나 모눈 일부가 이전 상태로 남지 않아야 합니다.
- 자동 검사에서 뷰포트 전체의 캔버스 크기, A4 밖 모눈 픽셀, 실제 hitTest, (1000,1300)/(1800,1600) 필기 좌표·삭제·복원, 창 확대, 용지 전환, 재열기 후 필기 영역 복원을 확인합니다.

## 가벼운 필기 보정

짧은 점, 직선, 원, 빠른 한글, 급한 방향 전환을 비교합니다. 모서리만 부드러워지고 글자 구조와 시작·끝점은 유지되어야 합니다. 펜을 떼기 직전과 직후 끝점이 움직이거나 획이 사라지지 않는지 확인합니다. 기존 문서를 재열어도 동일한 보정 경로가 표시되어야 하며 지우개도 그 경로에서 동작해야 합니다.

모델 검사는 보간 좌표 간격, 모서리 보정 범위, 시작·끝점 유지, 중복점 처리, 원본 입력 저장 보존을 검증합니다. 합성 이벤트 회귀 검사는 기존 빠른 입력·점·지우개·확대·저장·복원을 다시 확인합니다. 실제 필기감과 입력 지연은 마우스/Pencil 실사용 및 Instruments 확인이 필요합니다.

## 사각형 선택과 이동

V 또는 도구 모음의 사각형 선택 버튼으로 선택 모드에 들어갑니다. 영역을 드래그한 뒤 점선 상자 안쪽을 다시 드래그해 선택한 획 전체를 이동합니다. 빈 곳을 드래그하면 새로 선택하고 Esc 또는 P/E로 선택을 해제합니다.

합성 이벤트 검사는 20개 점의 사각형 선택, 이동 미리보기 중 원본 불변, 전체 이동, 한 단계 Undo/Redo의 정확한 좌표·메타데이터·획 순서 복원, 이동 후 저장, 50%/200%에서 선택 이동 좌표를 확인합니다. 실제 트랙패드/Pencil 조작감은 별도 실사용 확인 대상입니다.

## 빠른 회전 입력의 각짐 회귀 검사

16구간으로 성기게 입력한 원에 형태 보존 3차 곡선을 적용하고, 원래 입력점과 시작·끝점을 정확히 통과하는지 확인합니다. 보간점 간격, 기준 원의 평균 반경 오차 감소, 원본 경계 내 유지, 중복점 처리도 검사합니다. 실제로 빠르게 원·나선을 그린 후 입력 중 마지막 구간과 완료 후 곡선을 비교하세요. 실제 OS에서 전달되지 않은 샘플을 복구하는 기능은 아니며, 실기기 필기감과 지연은 별도 확인이 필요합니다.

## 자동 저장 및 마지막 문서 복원

새 노트를 만들면 저장 대화상자 없이 Application Support/LightNote/Notes에 .lightnote가 생성되어야 합니다. 입력 후 수 초 기다려 파일 획 개수가 증가하는지 확인합니다. 입력 직후 창 닫기와 ⌘Q도 확인하며 저장 창 없이 종료된 뒤 재실행 시 같은 파일이 열려야 합니다. 여러 노트 사이를 전환한 뒤 마지막으로 사용한 노트가 다시 열리는지도 점검합니다. 읽기 전용 파일 등의 저장 실패 시 오류를 알리고 종료가 취소되어야 합니다.

자동 통합 검사에서는 임시 폴더에 새 노트를 자동 배정하고 수정·재저장 시 경로 유지, draft 해제, 수정 표시 해제, 정확한 재열기를 확인합니다. 실제 UI에서도 무저장 버튼 입력, 디스크 자동 저장, 저장 창 없는 종료와 동일 파일 재실행을 확인했습니다.

## 일시적인 레이저

L 또는 레이저 버튼으로 선택한 뒤 눌러서 그립니다. 3초 이상 누르고 있어도 처음부터 끝까지 궤적이 유지되어야 합니다. 손을 뗀 시점부터 1초간 그대로 유지되고, 다음 2초간 연속적으로 흐려져 완전히 사라져야 합니다. 이전 궤적이 아직 보일 때 다시 누르면 이전 궤적도 현재 투명도를 유지해야 합니다. 다시 손을 뗀 순간부터 남은 모든 궤적이 1초 유지 후 2초간 사라져야 합니다. 레이저를 사용한 후 저장·재열기 시 일반 필기와 획 개수, Undo 기록이 바뀌지 않아야 합니다.

자동 검사는 1초 유지/2초 페이드의 시간별 투명도, 오랫동안 누른 상태 유지, 손을 뗀 뒤 만료, L 선택, 노트 저장과 Undo 기록에 포함되지 않는 것을 검증합니다. 저장·도구 선택 반복·배율 변경 같은 공통 입력 종료 호출만으로 홀드 중인 레이저가 사라지기 시작하지 않아야 합니다. 창 밖에서 mouseUp 전달이 누락되면 실제 버튼 상태를 확인하여 해제를 감지합니다. 활성 입력과 남은 레이저가 모두 없으면 타이머를 정지합니다.
